    what: 'A plan stores its own markdown pages, which lie over its repo''s files: doc links name them by path, check, briefs and the served docs read them, the CLI edits them, and import and export carry them.'
    details: 'A page is a `PageRow` in a partition keyed by project, plan and revision, sorted by path, with a version and its markdown. A whole-plan write that carries pages (`PlanWrite.pages`, `None` to keep them) writes them under its new revision and makes them current in its flip, so an import lands whole. The plan''s row names the pages'' revision apart from the nodes'' (`pages_current`, `pages_retired`), so a batch of node writes leaves the pages where they are, and `recover` prunes each table only of revisions it doesn''t read. `Store::edit_page_checked` writes or takes out one page in place, by version, under the plan''s write lock, and `Store::snapshot` reads nodes and pages at one moment. reef-render''s `Layered` reads the plan''s pages over `RepoSource`, naming paths as the repo does, and `Cached` lets a write''s before and after read each repo doc once; every build in the service goes through them, `next_over` with one per plan, and `doc_page` reads only the pages a path could be. Routes: `GET`/`POST …/pages` and `GET …/pages/{*path}`, with `PUT …/revision` and the page edits taking 48 MiB bodies; an edit is a `pages-put` change. `reef page ls|get|put|rm` edit by a `<!-- version: N -->` first line, and `put` says when a page hides a repo file. `reef import` keeps each markdown file in `src` that isn''t a node''s as a page at its path from `src`: a node''s link to it becomes that path, a page''s links to pages stay as written, and its other links lead to the repo from where it is; a link a page would hide, or a page with a node''s frontmatter, is refused. `reef export` writes each page at its path under `src`, listed under `# Pages` in the summary. reef-app follows `pages-put`, and an open section is read again after each change. A page path is relative, `/`-separated, with no part starting with `.`, no `#`, `?` or `\`, ending `.md`, never `SUMMARY.md`; a plan''s pages hold at most 32 MiB, and bulk writes go in bundles of 256 rows or 16 MiB. The schema moved, so a data directory needs starting fresh. This plan, imported into a scratch plan with its book taken away, checks clean and serves all six of its pages. Known limits: a page''s link into a node''s file leads to the book''s file, so only while the book is kept; a ```` ```reef ```` fence''s `page` in a node''s body is still left as written; a page taken out and put again starts at version 1; a page hides a repo file silently unless `reef page put` or import notices.'

cluttering a project's docs. The last step imports this book itself.
