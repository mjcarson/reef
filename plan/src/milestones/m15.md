  description:
    why: History is kept a partition per node and plan rows carry no times, so when a plan last changed, by whom, and what went done today can't be asked without reading every node's history.
    what: Each write to a plan's nodes or pages also keeps a plan-wide entry of when, who, which nodes and pages and which went done, from which the store answers a plan's last update and its nodes done in any window.
    details: |
      A new `ActivityRow` table, partitioned by project and plan and keyed as an edit is, so the
      newest sorts first. It joined the schema last, so no other table's fingerprint moved and no
      data directory is replaced for it. `keep_edits` tells each plan's `reef_api::Activity` from
      the write's `node/…` and `page/…` subjects, a start's left out, and sends it in the first
      bundle of the write's edit rows, under their key. A node set done, or added already done,
      went done (`Pending::went_done`). A node moved in done counts in neither plan.

      `Store::plan_updated` answers the newest entry as an `Updated`, else the plan's listing
      (`plan/<plan>`'s `Added`), so a plan none of whose writes was kept answers its listing until
      its next write. `Store::plan_done(plan, window)` reads the window from its end back, a page
      at a time, and keeps only the nodes done now, so one set back or removed isn't counted. No
      route yet: C120's summary calls them.

    details: |
      `GET /api/v1/projects/{p}/plan-summaries`, answering a `PlanSummary` a plan beside `PlanInfo`
      (`crates/reef-api/src/project.rs`). Its state is testing, sessions or none. Its workers are
      each node in progress with its work record's `started_by`, and each live session with its
      `attached_by` and its loop's node, matched on the pane as `central/reef-app/src/session.rs`
      does.

      Built: the route sits beside `…/plans` rather than under it as `…/plans/summary`, where a plan
      named `summary` would lose its own read, as user history sits beside `/users`.
      `Service::plan_summaries` (`central/reef-service/src/service/summary.rs`) reads the project's
      plans, work records, loops, sessions and runs once, then each plan's nodes,
      `Store::plan_updated` and `Store::plan_done` over the last 24 hours. A `PlanSummary` carries
      the plan's `PlanInfo`, the commit a remote project's branch was fetched at (none for a local
      project's working tree), `NodeCounts` of its nodes that aren't groups, its `updated`, its
      `done_today` ids, `Working` for each node in progress (its newest record's `started_by`, or
      nobody for one set in progress with no start), each `LiveSession` and `LiveRun`, its
      `PlanState` and `active`.

      Live means `Session::live` and `TestRun::live`: a session detached, as well as one gone, and a
      run that ended or went silent count for nothing. A session's loop is the one on its pane, else
      the group member its pane works (`member_of`). Its plan is its node's, else its loop's, else
      its own; a run's is its own. One that names none is its project's only plan's, or no plan's in
      a project of several. `reef plan ls --long` prints each plan's listing, then beneath it
      whether it is active, its state, its nodes done, those done in the last 24 hours, its last
      update and who made it, and a line for each node in progress, live session and run.

      hands it to `upgrade --finish` as a file, and adds the admin once the record names the
      release up; with `--host` it is asked here, from the host's facts. `served::without_sign_in_off`
      makes the key's line a comment, the file kept as `config.toml.before-sign-in`, or
      `.before-reefadm` on an adopt. Every reef-service fixture signs in as `tester`, its login kept
      for the CLI, git's hooks, the follower and a runner's stub; reef-app's suite and `check.py`
