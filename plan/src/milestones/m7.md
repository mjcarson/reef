      context, and calls a file binary as git does. The carry merges trees as `git merge-tree

      revision. The snapshot stays git's CLI, on a copy of the index.

      A seal leaves out untracked files no commit or add took, since a node's work is what it
      commits or stages: the snapshot is `git add -u`, then only the untracked files the base
      holds, then `git write-tree`. So a `__pycache__` its run left stays out, and what a start
      took along isn't shown as deleted.

      `reef node capture [ID]` finds the node its worktree is on with
      `reef_api::work::on_worktree`, or the one named, which must be worked there, and sends every
      file with its hunks through `POST …/work/{id}/captures`, which takes up to 48 MiB. The
      service keeps it as the node's next revision: a `RevisionRow` in the node's partition
      listing its files without their hunks, and a `RevisionFileRow` a file in the revision's,
      written first. Revisions count from 1 and go on through a restart. A capture whose base and
      tree are the latest revision's adds none, and its SHAs name the latest. A file whose row
      would pass 32 MiB is kept without its hunks. `…/revisions`, `…/revisions/{n}` and
      `…/revisions/{n}/files/{*path}` serve them, as do the app's `revisions` and
      `revision_file`, and each revision kept is a `revision-captured` change. A line's `Anchor`
      is its revision, its file, and its number on the side it is on.

      Known limits: every capture seals, since drafts are C56's, and no revision is ever pruned.
      Tried on a clone of this repo against a scratch `reef-serve`: the new binary read a data
      directory the installed one, from before C30, wrote, so the two new tables needed no fresh

      A line is followed a revision at a time by comparing the two revisions' stored hunks.
      Blobs tie them where they can: the same worktree blob holds the line where it was, and a
      worktree that is the next revision's base holds it as that base's line, as a round of fixes
      after the work landed sees. Otherwise the two sides' hunk lines are aligned as a patience
      diff aligns them: a shared base's lines by number, any other by text, the run between two
      hunks matching nothing, and a bounded LCS where no line found once in each anchors a run.
      A line is followed only to one the next revision's hunks hold on the same side; anything
      else outdates its thread from that revision, and it is followed no further. The next
      revision's file is the one under the same path, else one moved from the same base path,
      else one with the same worktree blob.

      Resolved threads follow too, and a thread started on an older revision is followed at
      once, under the comment lock a follow takes. Each thread a follow writes moves its version
      on, and a capture that moved any is a `threads-followed` change. The app reads its threads
      again on it, draws each in every revision it was followed to, names it where its line is
      now, and marks an outdated one with a tag and a dashed edge. check.py moved C35's resolved
      thread with a line added above it and outdated one on a deleted line, both still shown in
      revision 2.

      Known limits: in a file whose base and worktree both changed, lines are matched by text
      alone, so of two equal lines the order decides; a run of more than a million cells with no
      unique line is left unaligned, which outdates a thread in it.

# M7 Code tied to its node

Each node keeps the diff that did its work. Commits are squashed regularly, so reef reads git
only to capture a node's changes, and stores them itself. The user comments on the changed lines.

reef's CLI extracts the changes from the node's local checkout, and nothing is pushed or
fetched. git's hooks keep a draft current while the node is worked on, and Claude Code's Stop
hook seals it once the node is done.

[X3](../design/code-and-comments.md#what-x3-found) found how to pick out one node's changes. Its
diff runs from where it started, carried over whatever its base branch brought in since. Nodes
worked on at once each get a worktree, and nodes in a row share a branch.

```reef
focus = "M7"
```
