    details: |
      A loop can't be keyed on the session id: X4 found that every `/clear`, including a plan
      approval's, starts a new session. SessionStart(clear) hands the loop to the new one.

      Built in `crates/reef-api/src/loops.rs`, `central/reef-service/src/store/loops.rs` and
      `service/loops.rs`, and `crates/reef/src/loops.rs`. A loop is kept by its `Pane`: zellij's
      session and pane, else tmux's socket and pane, else `CLAUDE_PID`, the Claude Code process,
      which a clear keeps. A headless Claude Code 2.1.327 run showed its Bash commands and its
      SessionStart and Stop hooks all get `CLAUDE_PID` and `CLAUDE_CODE_SESSION_ID`, the
      session's current id. So `! reef loop start` finds its pane and session in the session's
      own pane, or `--pane` names one, as `reef loop ls` prints its key.

      Every loop is a `LoopRow` of one constant partition, keyed by its pane, so a pane keeps one
      loop, and every change (`POST /api/v1/loops`) reads them all under one lock. A start where
      a loop of the same project and plan is runs it again, and one of another is `busy`.
      `LoopEdit::Hold` takes a node, one at a time, refused as `held` while another loop holds
      it, for next_task (C40). `LoopEdit::Acted` records the node whose end the Stop hook acted
      on (C41). `reef hook session-start` reads the hook's `session_id` and hands it the pane's
      loop, printing nothing, since a SessionStart hook's output is added to the context.

      Tried live in a headless session against a scratch `reef-serve`: the loop Claude's Bash
      started was found by its Stop hook in the same pane, and handed over. The new table moved
      the schema's pin, but the binary read back a data directory C37's wrote.

      Known limits: a loop whose pane closed stays until `reef loop stop --pane` ends it, holding
      its node meanwhile. Nothing installs the hook until C42.

# M8 Claude fed from the terminal

The loop in the user's own Claude Code session. next_task hands Claude the next node by the
user's queue. Claude plans it in plan mode, the user answers its questions and approves the plan,
and Claude implements it and marks it done. Claude then resolves any open comments, and the Stop
hook clears the context and starts the next node. [X4](../design/feed-loop.md#the-terminal-loop) proves the pieces
first.
