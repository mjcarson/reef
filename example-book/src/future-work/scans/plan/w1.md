nodes:
  - id: "Class"
    title: "A scan class on every table shard"
    status: done
    description:
      why: "A table shard's walk reads share the medium queue with every get's partition read, and nothing yields, so a scan would compete as an equal with the reads a get waits on."
      what: "Every table shard has a scan queue below the foreground, its loops yielding every 64 KiB, and a second inbox on its loop drained only when the main inbox is empty."
  - id: "Budget"
    title: "A budget for transient read buffers"
    status: done
    description:
      why: "A walk page or an answer in a shard's outbox is charged to nothing, so a scan's pages could push a node past `node_memory` and evict every table's hot set."
      what: "Every buffer of a scan's page is drawn from `resources.scan_memory` before it is allocated, and a draw not met in 250 ms is shed by name."
  - id: "Pace"
    title: "Table reads paced by a device's idle time"
    status: done
    description:
      why: "Table storage has no pacing, and a table's archives share a device with its WAL, so a scan at device speed would queue every get's read and commit's flush behind it."
      what: "A scan's archived reads draw from one pace a device, under `scans.ceiling` and in the device's idle time, with a small `scans.trickle` always allowed so a busy device cannot starve it."
  - id: "Admit"
    title: "An admission class apart from the drivers'"
    status: done
    description:
      why: "A shard reads at most two walk pages at once; if client scans shared that count, a client scanning a table could shed the backfill that brings a stale copy current."
      what: "A scan's pages count by `scans.pages_in_flight`, apart from the drivers' `PAGES_IN_FLIGHT`, so the drivers keep their two pages whatever clients do."
  - id: "Read1"
    title: "One operation a record read"
    status: done
    description:
      why: "An archived record's read costs three operations, an `fcntl`, the read and a close, each awaited alone, and M23 is judged on a scan's rate within W12's cost budget."
      what: "An archived record's read borrows its archive's cached file handle for the read alone, so a record is one operation, its read."
  - id: "Sorted"
    title: "Merges written in key order"
    status: done
    description:
      why: "A merge writes its partitions in a `HashMap`'s random order, leaving a tablet's records about 870 KB apart, so a scan cannot read them in runs within M23's cost budget."
      what: "A merge writes its records and fragments in key order, so each tablet's records of a merge lie in one stretch of its block."
